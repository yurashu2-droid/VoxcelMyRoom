# Voxel / Pixel — Rendering Lab

内部の3D Voxelを、回転できる2Dドット絵風スプライトとして描く技術PoC。TypeScript / Vite / Three.jsのみ。バックエンド、生成AI、画像認識、外部モデルは不要です。

## 1. 起動

Node.js 20.19以上、または22.12以上を使用します。

```sh
npm install
npm run dev
```

表示されたローカルURL（通常 http://127.0.0.1:5173）をブラウザで開きます。依存関係の初回インストール後、外部通信なしで利用できます。WebGL2対応ブラウザが必要です。

```sh
npm run build    # TypeScript検査 + 本番ビルド
npm run preview  # distのローカル確認
```

最初は **Mode 3 / 128px / Pitch 22.5° / Yaw 45° / 4段階 / 22.5°固定回転 / ドット保持拡大**。ドラッグでY軸360°回転、縦・斜めドラッグで上下の角度も変更できます。表示領域にフォーカスして矢印キーでも1方向ずつ回せます。「180° 裏側へ」は背面確認用、「リセット」は視点と拡大率を初期位置へ戻します。

### ドット保持拡大と固定方向

- **ドットを保持**（既定）：ホイール・ピンチ・ZoomはCanvasの表示サイズだけを整数倍で変更します。投影範囲と元の128pxなどのラスタは不変。同じ角度なら拡大してもドット配置・色・原寸PNGは完全に同じです。Zoomの数値はフィット時に対する要求倍率で、実際の表示は最寄りの整数ピクセル倍率になります。大きく拡大すると画面からはみ出しますが、元画像は欠けません。
- **カメラズーム**：従来のOrthographic表示範囲変更。比較用に残してあり、こちらは拡大するとドット配置が変わります。
- **22.5°刻み**（既定）：横は16方向、縦は−67.5°〜+67.5°の7段階。中間角度は描きません。
- **45°刻み**：横は8方向、縦は−45°・0°・45°。8方向スプライト寄りの比較用です。
- **自由回転**：連続角度。縦は−67.5°〜+67.5°。自動回転にも選択した刻みが適用されます。
- ドラッグの入力は連続的に蓄積し、描画時のYaw・Pitchの両方を丸めます。斜め操作でも固定角度の組合せだけが表示され、方向間の補間アニメーションはありません。

## 2. 構成とレンダリング方式

### 格子・ステッチの追加実験

**現在の中心となる実験は「Voxelをドットで描く」です。** 各Voxelを1個のPoint Sprite（四角）として配置し、3D投影した中心を共通の表示マスへスナップします。各四角の色はそのVoxelの色、重なるマスは深度テストで手前を採用。面に格子を重ねる方式とは異なります。128pxのまま描き、拡大時のドット保持も利用できます。

この方式のVoxel Sizeはマス内の四角の塗り面積に対応し、1px以上の隙間を残します。小さい解像度では整数pxに丸めるためサイズ操作が同じ見た目になる区間があります。「ブロック単位の陰影」で有限段階の色を適用でき、OFFでは元の色をそのまま使います。外周線と画面格子・ステッチ用設定は無効です。

### ドット絵向けの陰影

- 本体：各Voxelの露出方向と、光方向の最大24セルの簡易レイ検査から明度を決め、3〜5段階のパレットへ変換。暗部は紫寄りで、1個の四角内にグラデーションを作りません。照明の結果は光方向・形状変更時だけ更新します。
- 足元：「ドット網点」「3段階の色面」「従来のフラット影」を比較できます。低いVoxel（床から2セル以下）の投影を濃い接地影として追加。通常の投影影は内側と縁に分けます。
- 網点：固定した2×2配列の密度で中間影と縁を描写。1ドットの寸法を1〜3px、濃さを調整可能。時間ノイズ、ぼかし、半透明グラデーションは使いません。色面モードは有限の3段階の色で塗ります。
- 限界：床影は簡易投影で、壁への受け影はありません。低いVoxelの影を接地の近似に使うため厳密な接触判定ではありません。露出方向は隣接セルからの近似で、凹部や細部の陰影に割り切りがあります。Pitch 0°以下では床影は非表示です。

斜め投影では複数Voxelが同じマスへ重なり、手前以外は隠れます。したがって全Voxelが別々のマスに見える保証はなく、通常のCube描画から輪郭が変わる場合があります。表示マスの規則性を優先したPoCです。「Voxel隙間0.75」と角度を維持して比較するには「ドットの表現」を切り替えます。

「Voxelをドットで描く」は128pxのロボット・正面・45°刻みのプリセット。「Voxel隙間 0.75」は従来の隙間あり表示。画面格子とステッチは後処理方式の比較用として選択欄に残しています。

格子・ステッチではVoxel Sizeを一時的に1として、隙間のない形状を描きます。その後、画面座標に固定した模様を物体部分だけに適用。斜めで3Dの隙間が重なって起こる不規則な干渉を避けます。背景・影・外周線には模様を適用しません。通常表示へ戻すと元のVoxel Sizeが再び使われます。

- 格子間隔1は各ピクセル、2〜4は複数ピクセルごとの編み目。線の濃さと色も調整可能。
- 線幅は元画像の1/4px単位。十字ステッチでは残す十字の太さを変更。
- 128pxの形状を512pxへNearestで合成し細線を追加します。3Dを512pxで再描画する方式ではありません。格子PNG原寸は512px、PNG 4×は2048pxです。
- 格子表示は512pxの整数倍で拡大し、元の模様を維持します。狭い表示領域・高解像度でははみ出します。
- 模様は物体表面でなく画面に固定されています。回転で格子の下を形状が動く見え方になり、輪郭端では格子が切れます。ASCII文字への置換ではありません。

```text
src/
  voxel/types.ts               Voxel / VoxelObjectの公開データ型
  voxel/generators.ts          重複セルを上書きする簡単なboxビルダーと配色
  scenes/desk.ts               デスク、PC、椅子、植物
  scenes/room.ts               床、2枚の壁、ベッド、机、PC、棚、植物
  scenes/asymmetric.ts         片側アンテナ・異なる腕・背面パックのロボット
  renderer/VoxelRenderer.ts    可視面メッシュ、カメラ、ライト、操作設定
  renderer/PixelRenderPipeline.ts 低解像度RT、合成、PNG出力
  renderer/PixelShader.ts      段階陰影とスクリーン空間の外周線
  main.ts                     UIとポインター操作
  style.css                   表示領域と操作パネル
```

```ts
type Voxel = { x: number; y: number; z: number; color: string };
type VoxelObject = { name: string; voxels: Voxel[] };
```

座標は整数セル、Yが上、色は `#RRGGBB` です。新しいデータは `renderer.setModel({ name, voxels })` に渡せます。読み込み時点で重複セルを解決してください。生成器はThree.jsに依存しません。`.vox` やAI、Room Scanのアダプターはこの形式へ変換するだけで描画部分を再利用できます。

同じデータから面法線付きの1枚のBufferGeometryを作ります。Voxel Size 1では隣接セルの内部面を削除し、同色面を境界なしで描きます。立方体ごとの線やテクスチャはありません。Voxel Sizeはセル間隔に対する立方体の辺長（0.65〜1.0）です。1未満は比較用の隙間あり表示になり、この場合は全ての面を生成します。Voxelの再サンプリングや全体スケールではありません。

## 3. Pixel Art化

1. **正投影**：遠近縮小がなく、角度を変えてもスプライトの寸法感を維持。
2. **低解像度RT**：64 / 96 / 128 / 160 / 256の正方形に一度描画。MSAAなし、`antialias:false`、DPRは1、RTのmin/magともNearestFilter。
3. **段階陰影**：面法線とワールド固定の光方向から明度を計算し、3〜5段階に量子化。暗部は紫寄り、明部は元の色を使用。さらにRGB各成分を32段階に丸め、滑らかなグラデーションを作りません。全画面32色という意味ではなく、素材色ごとの有限の色面です。
4. **外周線**：アルファを上下左右に1px参照し、形状の背景境界だけ濃い紫で縁取り。全Voxelの辺は縁取りません。モデルの穴にも輪郭が付きます。ON/OFF比較可能。
5. **フラットな影**：同じ形状を光方向へ床面投影。アルファを直接RTに書いてから背景と合成するため、三角形が重なっても濃くなりません。ボケ、接地グラデーション、PBR、ブルームは使用しません。
6. **整数倍表示**：利用可能領域に収まるCSS整数倍で拡大し `image-rendering: pixelated / crisp-edges` を指定。端数拡大を避けるため、解像度変更で表示領域の余白が変わる場合があります。

外周線と影は全モードで独立に切り替えられます。純粋なベースライン比較では両方OFFにしてください。

## 4. 普通のVoxel Renderingとの比較

| モード        | ラスタ解像度     | 陰影                                                       | 用途                 |
| ------------- | ---------------- | ---------------------------------------------------------- | -------------------- |
| 1 Original 3D | 表示サイズと同じ | Three.js MeshLambertMaterial + Ambient / Directional Light | 通常の3D比較         |
| 2 Low-res     | 選択した低解像度 | Mode 1と同じ連続明度                                       | ピクセル化だけの効果 |
| 3 Pixel Art   | 選択した低解像度 | 独自Shaderの固定段階色                                     | 最終候補             |

全モードでモデル・カメラ・ライト方向は共有します。回転は画像の差し替えではなく、同じ3D形状に対するカメラ回転です。スクリーン・前面装飾・背面パックは実際のVoxelなので、180°回転しても左右が勝手に入れ替わったり新しい形状が生成されたりしません。

## 5. Pixel Stabilizationと現在の問題点

- Stabilization ONではモデルの床中心を基準に投影行列をサブピクセル補正します。自由回転時のみYawを0.1°に微量量子化します。固定方向モードでは指定した22.5°または45°刻みを使います。静止時に時間由来の揺れ、ノイズ、TAAはありません。
- **回転中のエッジの1pxの出入りは残ります。** ラスタ格子を輪郭が横切るためで、位置補正だけでは解消できません。完全な手描きスプライトのドット配置を全角度で保証するものではありません。
- 64pxでは細い脚やアンテナが角度によって1pxに潰れたり途切れます。128〜160pxが細部とドット感のバランスを確認しやすい設定です。
- 部屋の壁は実体として存在し、背面からは内装を遮ります。自動的に壁を消すカットアウェイは未実装です。
- 影は床への簡易投影のみ。壁・家具への受け影、自己影はありません。Pitchが0°以下では床の裏面を見るため、投影影を非表示にします。
- 高いZoomではモデルや影が画像外に切れます。意図的な拡大であり、自動フィットはしません。
- Outlineは外周のみで、重なった同色パーツの内部境界までは検出しません。必要なら深度・法線バッファの比較を追加できます。
- 色処理は見た目優先の表示RGBパレットです。物理的な照明や厳密なカラーマネジメントを目的としません。
- 全面が軸に平行なVoxelなので、指定段階数の全てが同時に画面に出るとは限りません。
- ブラウザズームやOSの非整数DPIでは物理ピクセルの並びが均一でなくなる場合があります。PNG出力は厳密な整数サイズです。
- 小規模PoC向けのメッシュ生成です。大規模VoxelにはGreedy Meshing、チャンク化、Worker化が必要です。実機タッチ操作の検証は別途必要です。

## PNG保存

「PNG 原寸」は合成済み描画バッファをそのまま保存。「PNG 4×」はCanvas2Dの `imageSmoothingEnabled=false` で4倍に拡大します。背景・影・外周線を含み、UIは入りません。Mode 1ではネイティブ描画サイズでの出力です。透明背景出力は未実装です。

## 6. Sprite Stackingへ発展させる案

- VoxelObjectをYごとのRGBAスライスへ変換し、水平クアッドを積む別レンダラーを作る。データ形式とUIは共有する。
- 同じカメラ角度で現在の面メッシュ方式とStacking方式を切り替え、側面の隙間、上下の重なり、Pitchへの耐性を比較する。
- 各スライスの表示位置を画面ピクセル格子に合わせる。高さ方向の1px未満の間隔や、回転中の継ぎ目は別途検証する。
- 方位別Sprite Atlasの書き出しを追加し、ゲーム側では離散方向スプライトを使用。ライブ360°表示とは用途を分ける。
- 手描きの方向別パレット・アクセント・輪郭ルールを導入し、ラスタ結果のシルエットをさらに整える。

## 検証

開発サーバーで `/tests/render-check.html` を開くと実WebGL出力による23項目を検証。拡大前後の画像一致、固定方向、360°の同一性に加え、格子出力の解像度と画像保持、正面・斜めでの格子線の座標をピクセル単位で確認します。

`npm run build` で型検査と本番ビルド。ブラウザ上で3モデル、正面と背面、ドラッグ360°、Pitch、3モード、解像度変更、ライト、段階数、輪郭・影切り替え、PNG保存を確認。PNGは原寸と4倍版の各ピクセルを比較しNearest Neighbor拡大を検証しています。
